Privacy policy

Last updated: 9 November 2026

Morning Market Bot is a personal, self-hosted application that combines a market briefing with a Google agenda in a private Telegram message. The person operating the installation controls the connected accounts, host and delivery destination.

1. Google data accessed

With the user's authorization, Morning Market Bot requests the Google Calendar events read-only permission and the Google Tasks read-only permission. It uses these permissions only to read information for the requested morning agenda.

  • Google Calendar: Events overlapping the current local day in the calendars selected by the operator. The application reads event titles, start and end dates or times, event status, the authenticated user's invitation response, and identifiers needed to handle recurring events and duplicate invitations.
  • Google Tasks: Task-list identifiers and incomplete task records across the connected account's lists. It keeps dated task titles, identifiers, completion status and the scheduled calendar date exposed by the Tasks API. This includes future and past scheduled dates. Undated and completed tasks are omitted from the agenda. The separate Deadline field and task times are not read by this API connection.
  • Authorization: OAuth client credentials and a refresh token are stored locally so the worker can obtain temporary access tokens without a fresh sign-in every morning.

The application does not create, change, complete, delete or respond to Google events or tasks. Calendar snapshots do not retain event descriptions, locations, meeting links or attendee lists. Task notes and descriptions are not requested.

2. How data is used and shared

Google data is used solely to display the user's requested calendar and scheduled tasks in the morning Telegram brief. The application formats dates, excludes canceled events and the user's declined invitations, removes duplicate invitations where identifiable, and omits unavailable or stale agenda snapshots.

The operator-authorized agenda is transferred to Telegram as part of the message sent to the chat selected during setup. Telegram processes and stores these messages under its own privacy policy. The application communicates with Google and Telegram using HTTPS.

Calendar and task contents are not included in web searches, market-research prompts or AI model inputs. The separate market-research workflow can use stock symbols, company names and public financial information. Google Calendar and Tasks data is not used to develop, improve or train AI or machine-learning models.

Morning Market Bot does not sell Google user data, use it for advertising, provide it to data brokers, or use it to determine creditworthiness. Its use and transfer of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements.

3. Storage and protection

Google credentials and minimal agenda snapshots are stored on the operator-controlled host. An initial setup computer may retain its own copies. Saved delivery records also contain the formatted message text, including agenda items, to support reliable delivery and avoid duplicate sends.

The worker writes credential, snapshot and delivery files with restrictive file permissions on systems that support them. Temporary access tokens are used in memory rather than included in reports. The prepared Raspberry Pi deployment separates the market-research environment from the bot's Google credentials and agenda files.

The operator is responsible for host accounts, filesystem access, backups and device security. The application does not provide a managed encrypted storage service. The operator should keep private runtime files out of public repositories, website uploads and shared source archives.

These explanatory web pages contain no application login, forms, analytics, advertising, tracking scripts or application cookies. A hosting provider may process routine website requests under its own policies.

4. Retention and deletion

The latest calendar and task snapshots are replaced during subsequent refreshes. Saved delivery records, reports and operator-created backups are not automatically purged; they remain until the operator deletes them. Existing Telegram messages remain subject to Telegram's message-storage and deletion behavior.

To remove locally stored Google data, the operator can stop the worker and delete its Google authorization file, calendar and task snapshots, saved delivery records containing the agenda, and any copies or backups on setup computers and other hosts. Deleting delivery records while the scheduler is active can affect duplicate-send protection, so the worker should be stopped first.

To remove delivered agenda items, delete the relevant Telegram messages using Telegram's available controls. Revoking authorization stops future authorized Google reads but does not by itself erase local files, backups or messages already delivered.

5. Connection choices and changes

The user chooses whether to authorize Google access. The operator chooses the calendars, schedule, host and Telegram destination. Google access can be revoked at any time through the Google Account connections page. The operator can also disable the agenda or stop the bot.

This policy describes the current application. If its handling of Google data changes, the operator must update this policy and obtain any additional authorization that is required before using data in the new way.

6. Contact

For questions, connection help or deletion requests, contact the application operator using the support email displayed on the Google authorization screen. This personal application does not provide public user registration or a separate customer-support service.
